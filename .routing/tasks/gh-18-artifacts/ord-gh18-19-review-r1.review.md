## answers

1. **Callers and states.**
   - `read` — With no calculated position the wrapper uses `dropFold()`. When `showCorner()` handles leaving the corner it enters `read` and finishes the preview animation before calling the wrapper. `hovering` is still true, so `x <= 0` drops the preview and `x > 0` gives the library its usual return animation.
   - `fold_corner` — `settle()` finishes the preview animation first. That animation leaves the calculation and state in place. A preview position at or across the spine is dropped, and a positive position uses the normal return for the reachable preview geometries. This keeps the anchor on a mode switch. A hash jump subsequently sets its own anchor.
   - `user_fold` — A moved, non-swipe mouse or touch release and a held drag reached through `settle()` use the drag rules. A missing position or short portrait BACK position drops the fold. The rest use the library's spine decision. `settle()` finishes any prior animation before reaching this branch and any resulting animation before changing the page or mode. A direct release can reach the branch with an earlier committed animation still pending, which causes the important finding.
   - `flipping` — Hover handling skips it. Clicks and programmatic flips start their animation via `flip()`. In the normal settle path the first `finishAnimation()` commits the turn and clears the calculation before the wrapper runs. A new drag can overwrite the state before the animation finishes, so a `flipping` check at release would miss the regression.
2. **Direction and committed turns.** Installed page-flip 2.0.7 defines FORWARD as 0 and BACK as 1 in `Flip.ts:11`. The Chromium runtime reported direction 1 for ArrowLeft and a backward touch swipe, and 0 for the forward fold. A button, ArrowLeft, or swipe already animating when `settle()` begins completes in its first `finishAnimation()`. Chromium confirmed ArrowLeft during a portrait-to-spread switch reached `#/p/44`. The UI starts a recognized swipe through `flipPrev()` or `flipNext()` and `userStop(..., true)` skips the wrapper. A 70px fast backward touch swipe reached `#/p/44`. Each calculation retains the direction chosen at its start, so a FORWARD calculation cannot meet `shortBack`. The direct release overlap in the finding bypasses the settle safeguard.
3. **Preview classification.** `fold()` writes `user_fold` before reusing or creating a calculation. A drag begun from a corner preview is treated as a drag when released. A press with no movement goes through `flip()`. `showCorner()` writes `read` before calling `stopMove()` on hover exit, so the `hovering` flag remains necessary.
4. **Cleanup.** `dropFold()` clears both renderer page references and the shadow, sets `read`, and resets the calculation and controller page references. This matches page-flip's end-of-animation cleanup and works for the settled preview and an isolated short backward release. The helper leaves the renderer's animation callback scheduled. In the overlap, that callback loses its own calculation and can observe a later gesture's calculation. Relevant dependency paths are `web/node_modules/page-flip/src/Flip/Flip.ts:65`, `:344` and `web/node_modules/page-flip/src/Render/Render.ts:162`, `:176`.
5. **Normal behavior.** The prescribed checks passed at 1440×900, 390×844, and 1440×160. #18 changes the intended isolated short backward release in portrait. Landscape and portrait forward drags keep the library's stop rule. Hover exit, isolated clicks and navigation, and drags that cross their thresholds all passed. The overlapping portrait navigation failure is captured above.
6. **Comments and commits.** The #19 comment and commit correctly identify the retained `fold_corner` state and the old hover-exit flag. The library targets a 50px fold, and the actual resting position also depends on animation sampling. The #18 coordinate explanation and numeric direction are correct. Its midpoint wording is slightly narrower than the implemented comparator. Its claim that keys still turn holds for an isolated key press and misses the overlapping release described in the important finding.
